# 供应商对账与异常复核助手

**Vendor Reconciliation & Exception Review Assistant**

一个面向财务供应商月度对账场景的 Streamlit 工具。系统将内部系统账单与多家供应商账单进行逻辑校验、双向匹配和字段级差异识别，并按供应商整理待沟通事项，最终输出可下载的对账结果。

项目核心价值是把分散的供应商账单整理为一套可追溯的异常清单，帮助财务人员快速回答：哪些记录一致、哪些账单本身有问题、哪些记录需要向供应商或业务确认。

## 1. 项目简介

供应商月度账单对账通常不只是简单的金额相减，还需要同时检查计价逻辑、访谈编号、账期、内部系统记录和字段差异。本工具使用 Python 确定性规则完成这些检查，并将异常按供应商分组展示。

当前公开版本不调用真实 LLM，也不把模型作为最终审批或结算依据。所有演示数据均为模拟数据。

## 2. 业务背景

财务人员在对比内部系统记录和供应商账单时，常见问题包括：

- 普通访谈的单价、时长、倍率与供应商总价不一致。
- 供应商使用 15 分钟进位计价，而内部系统按实际时长记录。
- 0 结算、重复编号、跨账期编号或编号格式异常。
- 内部系统有记录但供应商账单缺失，或供应商有记录但系统中不存在。
- 双方记录均存在，但时长、倍率或金额存在字段级差异。
- 异常分散在不同账单中，难以直接整理为供应商沟通清单。

本项目把这些步骤整理为可重复运行的财务对账工作流。

## 3. 业务流程

```text
选择内置模拟数据或上传文件
        ↓
读取内部系统账单与供应商账单
        ↓
供应商账单逻辑校验
        ↓
内部系统 / 供应商账单双向匹配
        ↓
时长、倍率、金额字段差异识别
        ↓
按供应商整理待沟通事项
        ↓
下载完整对账结果
```

页面优先展示待沟通事项，正常记录和技术明细默认折叠，方便财务人员先处理异常。

## 4. 支持的账单类型

内置模拟数据包括：

- `sample_data/dayq_system.xlsx`：内部系统账单。
- `sample_data/Vendor_A_bill.xlsx`：Vendor A 供应商账单。
- `sample_data/Vendor_B_bill.xlsx`：Vendor B 供应商账单。
- `sample_data/Vendor_C_bill.xlsx`：Vendor C 供应商账单。

上传模式先选择内部系统账单，再选择一个或多个供应商账单。系统优先读取账单中的供应商字段；如果供应商账单没有该字段，才使用上传文件名作为显示标签，不要求用户遵守固定文件名格式。

## 5. 供应商账单逻辑校验

Python 负责供应商账单中可以确定判断的规则，包括：

- 普通访谈：单价 × 计价时长 × 倍率 = 理论金额。
- 15 分钟进位计价与实际时长计价。
- 数据采买 / 打包价跳过普通访谈乘法校验。
- 0 结算标记为无效访谈。
- 重复访谈编号识别。
- 跨账期访谈编号识别。
- 访谈编号末尾异常识别。

逻辑校验结果在页面中按供应商折叠展示。异常记录会进入“待沟通事项”，并保留原始项目、日期、金额和异常说明。

## 6. 双向匹配逻辑

系统按“供应商 + 访谈编号”进行双方记录匹配，保留以下情况：

- 双方均有且关键字段一致。
- 系统有 / 供应商账单无。
- 供应商账单有 / 系统无。
- 供应商账单存在重复编号。

“系统有 / 供应商账单无”和“供应商账单有 / 系统无”会直接进入供应商待沟通区域，并显示建议确认方和建议处理方式。

## 7. 字段差异识别

双方均有记录时，继续保留 V1.1 的字段级差异判断：

- 时长差异。
- 倍率差异。
- 金额差异。

如果金额存在差异但时长差异很小，页面会提示可能是分钟换算或小数位差异，建议与业务核对后以内部系统金额作为参考。倍率差异会提示确认录入方。其他金额差异会提示核对单价、时长、倍率和供应商选择。

系统不会自动决定最终结算金额。

## 8. 按供应商整理待沟通事项

“待沟通事项”是页面的核心区域，按供应商展开后分为：

1. 供应商账单自身逻辑异常。
2. 系统有 / 供应商账单无。
3. 供应商账单有 / 系统无。

每条事项会显示访谈编号、日期、项目名称、供应商金额、系统金额、问题类型、核心原因、建议处理和建议确认方。用户不需要回到原始明细表寻找上下文。

## 9. 人工确认机制

本工具只提供确定性初审和沟通整理建议：

- “双方一致”只表示当前字段检查通过。
- “账单逻辑异常”需要供应商或财务进一步确认。
- “系统有 / 供应商账单无”通常需要供应商确认是否漏记。
- “供应商账单有 / 系统无”需要业务确认是否实际发生、跨期或漏录。
- 字段级差异需要业务、供应商或财务根据实际口径确认。

最终结算金额、是否补充账单以及沟通结论，仍需由财务人员人工确认。

## 10. 结果导出

点击“下载供应商对账结果”可下载：

`vendor_reconciliation_result.xlsx`

文件保留以下内容：

- 全量账单逻辑校验。
- 全量双向匹配。
- 供应商问题汇总。
- 字段级差异。
- 每家供应商的逻辑异常。
- 每家供应商的系统有 / 供应商无。
- 每家供应商的供应商有 / 系统无。

## 12. 本地运行

建议使用 Python 3.9 或以上版本：

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 -m streamlit run app.py
```

打开页面后，在左侧选择“使用内置模拟数据”，点击“开始对账”即可运行完整流程。

## 13. 模拟数据与隐私

- 所有账单、访谈编号、人员信息、项目名称和供应商名称均为模拟数据。
- 项目不包含 API Key、Token、Password 或 `.env` 文件。
- 项目不包含真实员工、真实供应商或真实公司内部账单。
- 上传模式只在当前 Streamlit 运行过程中处理文件，不修改原始上传文件。

## 14. 当前限制

- 当前支持的输入结构以项目内置 Excel 模拟数据字段为基准。
- 如果真实企业导出字段差异较大，需要在解析或字段映射层适配。
- 账期仍通过访谈编号中的月份与当前模拟账期进行判断，生产环境应改为可配置参数。
- 当前页面提供待沟通建议，但不提供在线修改、回填和重新结算功能。
- 当前没有数据库、权限管理、操作日志或自动发送供应商沟通邮件。
- 当前公开版本没有调用真实 LLM，异常说明来自 Python 规则和固定文案。

## 15. 后续扩展

- 将账期、容差和字段映射外置为可维护配置。
- 支持更多供应商账单格式和批量月份处理。
- 增加页面内人工确认、修改记录和重新导出能力。
- 增加规则覆盖率、供应商差异趋势和月度异常跟踪。
- 后续可将 Python 已识别出的异常交给语义模型，用于辅助整理供应商沟通摘要或生成待确认事项说明，但不替代 Python 对账规则和财务人工确认。
